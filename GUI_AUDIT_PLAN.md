**GUI audit and improvement plan — 8 September 2026**

The four-stage workflow is worth retaining. The main usability problem is the amount of permanently visible configuration and the duplication of controls between stages. The first implementation work should address geometry provenance and result invalidation; simplifying the panels can then make the existing workflow easier to use without changing its numerical defaults.

This is a source and diagnostic audit of all four active workspaces, their event handlers, the relevant processing/export paths, and the installed kikuchipy 0.12.1 reader and detector implementation. All **35 existing tests passed** with `.venv/bin/python -m unittest discover -s tests -v`. Additional isolated probes reproduced the state and geometry issues described below. It is not a completed live visual or large-dataset performance certification: full numerical processing and a screen-by-screen interactive usability trial were not run. Application code and user datasets were not changed.

**Pattern center and beam/scan shift**

The correction is already implemented through `EBSDDetector.extrapolate_pc`, and the GUI already has unbinned detector pixel size and acquisition binning fields. The checkbox is **off by default**, so the pixel-size issues below affect correction when it is enabled. For an aligned, uniform raster with validated geometry, passing detector shape `(height, width)`, point positions `(row, column)`, and scan steps `(dy, dx)` is the right basic structure. Normal kikuchipy projections and refinement use the current point PCs; dictionary matching uses a representative PC and is therefore an approximation across a varying-PC scan. [Application correction](/Users/tvermeij/Dropbox/Work/Software/overlapEBSDIndexing/multistep_overlap_ebsd/core.py:4825), [kikuchipy correction documentation](https://kikuchipy.org/en/stable/reference/generated/kikuchipy.detectors.EBSDDetector.extrapolate_pc.html).

**The physical scale is not currently trustworthy automatically.** H5OINA loading copies `s.detector.px_size` into application metadata. The installed Oxford reader does not read a physical detector pitch into that detector, so this value is the library default **1.0**, not a measurement. UP loading correctly records pitch and binning as unknown, but the GUI starts at 1.0/1.0 and only overwrites fields when incoming values are present. Loading UP after H5OINA can therefore retain previous calibration values. Positive-value validation accepts these plausible-looking placeholders. Evidence: `core.py:3460`, `core.py:3616`, `gui.py:170`, `gui.py:2171`, `core.py:4852`.

For the local UP1 example, the header contains a 155 × 128 pattern shape and no physical detector pitch or binning. The companion ANG contains a 516-row × 271-column scan, 0.01 µm scan steps, and normalized PC values. Those scan steps describe motion across the specimen; they are not detector pixel size. The ANG `TEM_PIXperUM` field should not be used as EBSD detector pitch.

H5OINA may provide enough information to derive the detector scale, but this requires a validated interpretation. The official specification has optional `EBSD/Header/Lens Field View` in mm, camera mode, stored dimensions, and—in newer files—acquired dimensions. It does not define a dedicated physical detector-pixel-size field or fully specify the field-of-view/crop relationship. Consequently, automatic extraction should use a verified detector/export profile, with a manual fallback. Reduced-size pattern exports must be accounted for separately from acquisition binning. [Oxford H5OINA specification](https://github.com/oinanoanalysis/h5oina/blob/master/H5OINAFile.md).

Recommended geometry configuration:

- Physical pixel size is needed to derive scan-position corrections from beam displacement. Existing normalized per-point PCs can be used directly without this extra physical calibration.
- Make the basic choice explicit: **Keep imported per-point PCs**, **Apply one calibrated PC**, or **Apply calibration with scan-position correction**. Display the active choice on every tab.
- Internally use the effective detector-plane pitch of a **stored pattern pixel**, in µm, or equivalent calibrated detector width/height. This is the physical size represented on the detector/scintillator, not automatically the camera sensor's silicon pixel pitch.
- In advanced settings, allow unbinned detector-plane pitch × acquisition binning, plus any export resizing. Dictionary software binning must remain a separate parameter and must not be counted twice.
- Keep required missing inputs expanded. Use an empty/unknown state instead of 1.0. Show units and the source of each value: verified file metadata, detector profile, manual, or unknown. Clear unverified values when changing inputs.
- Read beam coordinates and scan rotation when available. The present implementation uses row/column and step sizes, not measured beam-position vectors. Validate scan-axis orientation, tilt, and rotation before claiming correction for rotated scans, nonuniform scans, or arbitrary beam offsets.
- Preview PCx/PCy/PCz over the map, identify the calibration reference location, and show both normalized changes and equivalent pattern-pixel displacement. Assess the magnitude from actual geometry instead of a general “below 50 µm” rule.
- Persist the exact calibration and its provenance with the applied PC map, workflows, dictionaries, and exports. Reapplying the same calibration should be idempotent.

**Proposed control hierarchy**

Keep the four tabs. Each tab should place its next action, prerequisites, ROI, and result status above the fold. Use named expandable sections whose closed summaries show nondefault settings. Any missing required value should automatically expand its section. Avoid a single global “expert mode” that hides all context.

| Workspace | Keep visible | Put in expandable sections or menus |
|---|---|---|
| Load and PC calibration | Input and master files; selected phase by name; import/geometry summary; calibration-point list with Add/Remove; Optimize; PC application mode; required detector scale when unknown | File-format overrides; UP geometry and PC convention; pattern conditioning; energy model; calibration search limits; manual Euler/PC editor |
| Dictionary indexing | ROI; dictionary identity/status; angular spacing and software binning; Generate/Load; one Run action with a choice of primary-only, through residuals, or through mixture fitting | Dictionary Save/Save As and full path; retained candidate count; refinement limits; manual selected-point and individual-stage actions |
| Residual indexing | Shared ROI summary with Edit link; minimum primary NCC; Analyze ROI; selected-point diagnostic; processing coverage | Individual Fit/Index/Refine actions; blur/gain bounds; iterations/population; candidate count; refinement limits; worker count; residual-pattern writing |
| Mixture optimization | Shared ROI; minimum residual NCC; Fit ROI; selected-point result and fit quality; export | Optimizer limits; orientation search limits; selected-point orientation refinement; worker count; shared gain/blur bounds |
| Shared application controls | Active dataset, geometry state, dictionary state, ROI, current job, unsaved/modified state | File menu for workflow Open/Save/Save As and exports; collapsible log and technical details; display options beside plots |

Keep familiar scientific controls such as angular spacing, binning, and NCC thresholds easy to reach. Move numerical optimizer tuning and defaults out of the main path. The current 12° dictionary default should be described as a coarse starting point; do not silently replace it during a visual refactor. Any proposed presets should show their exact settings and be validated on representative datasets before being described as suitable for final analysis.

Specific usability/functionality improvements:

- Replace `maxfev`, `keep_n`, “trust Euler,” and `-1/0/N` with “Maximum evaluations,” “Retained matches,” “Orientation search range (°),” and named mask choices with a conditional radius field.
- Use one selection model. Row/column/index edits should synchronize on commit; display a point's saved values when selection changes. Mark uncommitted Euler/PC edits as a preview with Apply/Revert.
- Add the missing Remove Calibration Point control; the handler already exists. Show selected points in a compact list with fit success and deviation, so outliers can be excluded individually.
- Show phase names and master-pattern phase compatibility. The current phase auto-selection includes phase 0, so a mostly unindexed map can select that as its target. Explain the intended target phase explicitly.
- Show which settings are shared between tabs. Primary/refinement controls and gain/blur bounds currently reuse variables; an edit on one tab can alter another stage's behavior.
- Separate display thresholds from processing thresholds in wording and placement. Avoid treating a native ANG CI column as actual NCC/DP without provenance (`core.py:3583`).
- Make form validation consistent: finite numbers, valid ranges, units, and actionable inline messages. Threshold parsers currently substitute 0.15 for invalid text and accept `NaN`; several button handlers parse other values outside their error handling.
- Disable incompatible actions with a short prerequisite explanation. Busy state currently does not disable controls, and a second action can appear to do nothing. Snapshot settings before starting work and update Tk widgets only through the UI thread.
- Add cooperative cancellation at safe batch/stage boundaries and preserve completed work. Currently closing is blocked until work finishes, with no Cancel action. Show counts completed/skipped/failed; stage-count progress is not a reliable elapsed-time estimate.
- Keep source, primary, residual, and mixture map labels distinct. Mark unprocessed, rejected, failed, and outdated points separately; a white pixel alone is ambiguous. Add an enlarge-panel action for the dense six/eight-panel views.
- Only let primary-button clicks select map points when pan/zoom is inactive. The current callback does not check the mouse button or navigation mode, so toolbar gestures may interfere with inspection; confirm this in live UI testing.
- Make the export dialog show actual scope, format, included patterns, estimated size, and overwrite target. “ROI” exports preserve full-map dimensions; offer “full map with ROI results” explicitly, and add a cropped export only as a separate extension. Disable ANG choice when the current H5OINA path forces H5OINA.
- Replace machine-specific prefilled file paths with recent files or an empty start screen. Add keyboard shortcuts for workflow save/open and point navigation. Test control scrolling on macOS trackpads and other platforms; current scrolling uses global mouse-wheel bindings.
- Consolidate common controls and remove dormant alternate builders after the behavioral fixes. The active workspaces are built at `gui.py:256–338`; old `_build_left`/`_build_right` scaffolding should not be mistaken for additional currently visible controls.
- Record a tested dependency set. `requirements_gui.txt` currently has no version bounds, while reader and detector behavior directly affect geometry; dependency upgrades need the geometry/round-trip regressions.

**Suggested implementation sequence and completion criteria**

1. **Correct scientific state and geometry.** Implement geometry provenance, valid input requirements, authoritative result lookup/invalidation, current dictionary PC selection, legacy projection fixes, and PC-map round trips. Add focused synthetic regressions for the reproduced defects. Confirm that changing PC changes projections, that obsolete results cannot be exported, and that save/reload retains the applied geometry.
2. **Make running jobs predictable.** Introduce immutable job settings, main-thread UI updates, early busy guards, safe cancellation, and explicit prerequisites. Confirm that opening a workflow during a job cannot change the active workflow and that edits made during processing cannot silently invalidate a just-finished job.
3. **Simplify the four existing workspaces.** Add the shared status strip, named expandable sections, main Run actions, calibration list, coherent selection editor, and consolidated save/export dialogs. Preserve numerical defaults and keep manual actions available. Demonstrate a routine analysis without opening optimizer sections.
4. **Validate the complete user journey, then extend.** Test load → calibration → dictionary → residual → mixture → export → reopen, for UP1/UP2 and genuine H5OINA files. Include rotated scans, non-square patterns, missing detector scale, resized exports, uneven calibration-point selections, interruption, and datasets with unindexed points. Check small/laptop windows, high-DPI displays, keyboard operation, trackpad scrolling, and long-operation responsiveness. After this, add reusable detector profiles, optional calibration outlier rejection/plane fitting, and validated processing presets.

Useful release gates: full-resolution versus software-binned physical correction agrees; applying identical calibration twice does not drift; current-PC dictionaries use the documented reference; changing a fit input invalidates every affected descendant; selected-point tools work after ROI processing and workflow restore; exports accurately describe their masks, geometry, and settings.

No valid real H5OINA fixture was available during this audit. The local `reindexed_output_30x30.h5oina` is ANG text despite its suffix; this is an existing local-file anomaly, not evidence that the current tested H5 exporter produces invalid files. Include a genuine Oxford-exported fixture before certifying automatic metadata behavior.
